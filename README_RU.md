# PICO 4 Motion Tracker Unlock (2.0.5)

Полная разблокировка приложения PICO Motion Tracker **2.0.5** для **PICO 4 standard** (A8110 / Phoenix, CN ROM 5.13.7).
Приложение «Трекеры движения 2.0.5» из версии Ultra полностью перенесено через **Magisk-модуль**,
с переключением режимов трекинга на **2 / 3 / 5 точек**. Системный раздел не изменяется — удаление модуля возвращает всё как было.

> 📦 Загрузка: [Releases](../../releases) → `PICO4_MotionTracker_2.0.5_v2.2.zip`
> 🔧 Требования: Magisk 27+, PICO 4 (standard / другие модели 4-й серии с теми же ограничениями)

---

## ✨ Что разблокируется

| Возможность | Сток (standard) | После разблокировки |
|---|---|---|
| Приложение Motion Tracker 2.0.5 | «Устройство не поддерживается, обновите систему» | Полностью работает |
| Лимит сопряжённых трекеров | 2 или 3 (зависит от режима ношения) | **2 / 3 / 5, переключается в приложении** |
| Привилегированные разрешения | Недоступны (несовпадение подписи) | Полный доступ уровня priv-app |
| 5 точек (5tk_thigh) | Только для Ultra | Открыто на уровне системы (см. ниже) |

## 📥 Установка

1. Убедитесь, что есть root (Magisk 27+)
2. Magisk → Модули → Установить из хранилища → `PICO4_MotionTracker_2.0.5_v2.2.zip`
3. Перезагрузка
4. Откройте приложение «Трекеры движения»: сопряжение → калибровка → вперёд

## 🗑️ Удаление

Удалите модуль в Magisk → перезагрузка. Системный раздел не затронут, всё возвращается к стоку.

## 🔄 Переключение режимов (2 / 3 / 5 точек)

- **Настройки → Лимит трекеров**: выберите 3 или 5 (если сопряжённых устройств больше целевого значения, появится штатное окно «сначала отвяжите»)
- **Страница режима ношения**: переключение 2 точки (2tk) / 3 точки (3tk_waist) / 5 точек (5tk_thigh); при подтверждении **лимит сопряжения синхронизируется автоматически** (2т→2, 3т→3, 5т→5)
- Все переключения вступают в силу сразу, без записи в системный конфиг-сервис PICO

> ⚠️ **Внимание: у меня только 3 трекера, протестировать сопряжение 5 не удалось.**
> Признаки на уровне системы (MCU `tracker_num=5`, Stationservice работает с 5 слотами) говорят,
> что 5 точек возможны, но полная конфигурация из 5 трекеров на реальном железе не проверена.
> Если возникнут проблемы при сопряжении после 3-го трекера — создайте issue с logcat.

## 🧩 Как это работает: почему так много слоёв

Приложение не запускается на standard из-за **пяти вложенных ограничений**:

| # | Слой | Сток | Решение |
|---|---|---|---|
| 1 | Флаг продуктовой линейки | `ro.pxr.externalfunc=0` → «устройство не поддерживается» | priv-app overlay + принудительное прохождение проверок |
| 2 | Привилегированные разрешения | Установка в /data с тестовой подписью не даёт `SWIFT_ACCESS` и т.п. (signature\|privileged) | Magisk overlay в `/system/priv-app`, разрешения выдаются по логике «или» |
| 3 | Нативная совместимость | `libswift.so` 2.0.5 требует экспорт `getSwiftTrackerInfoVector`, отсутствующий на P4 → мусорные данные идут в JNI → цикл крашей `negative array length` | Путь вызова через соответствующий vtable-слот отключён |
| 4 | Перечисление устройств | Энумерация неработоспособна, список всегда пуст, калибровка недоступна | Список устройств построен на системном `statusChangedCallback` |
| 5 | Переключение режимов | Конфиг-сервис PICO отклоняет запись системных ключей (режим застрял на 5 точках, лимит на 5) | In-app override, мгновенный эффект |

Также: discovery-переключатель, нужный для сопряжения, игнорировался проверками питания/видимости приложения — теперь принудительно включён
(именно это было причиной «нажимаешь сканирование — тишина»).

Полная история реверса — изменения smali, бинарные патчи ARM64 и разбор цепочки крашей — в
[FIX_NOTES.md](FIX_NOTES.md) (включая полный разбор `negative array length: -954437177`).

## 🆚 Сравнение со старым подходом (LSPosed / Zygisk hook)

Изначально в репозитории было LSPosed-hook-решение (удалено в v2.0):

| | LSPosed hook (старое) | Magisk priv-app overlay (новое) |
|---|---|---|
| Подход | Перехват проверок рантайм-хуками | Замена приложения + бинарные патчи |
| Риск крашей | Высокий (ClassLoader re-entry на handleLoadPackage → цикл крашей; хардкод в телах методов хуками не достать) | Нет хуков, изменения зафиксированы в APK |
| Разрешения | Priv-app привилегии всё равно недоступны | ✅ Выданы полностью |
| Нативный слой | Не покрыт (Xposed не хукает native) | ✅ Пропатчен напрямую |
| Зависимости | Нужен фреймворк Zygisk Vector | Только Magisk |
| Поддержка | Каждое смещение — правка кода | После OTA — перепрошить модуль |

## ❓ FAQ

**В: Нажимаю сканирование — ничего не происходит?**
Убедитесь, что приложение 2.0.5 и модуль установлен (с перезагрузкой). В v2.0 discovery включён принудительно;
если проблема осталась — приложите logcat с фильтром `SwiftRepo|TrackingClient` к issue.

**В: Трекер отваливается через несколько секунд после сопряжения?**
В логе `reason: tracker_power_off` при корректных настройках на стороне шлема —
проблема в прошивке самого трекера (обычно после отвязки включённого трекера).
**Положите его на зарядную станцию на несколько минут или сделайте сброс к заводским**, затем сопрягите заново.

**В: Работает ли режим 5 точек?**
Все программные ограничения сняты. Но для 5 точек нужно 5 трекеров — у меня только 3, протестировать сопряжение 5 не удалось.

**В: Перестало работать после OTA?**
Ожидаемо. После OTA нужно перепрошить модуль и перезагрузиться.

## ❓ Дополнительные вопросы
**В: Приложение ждёт «DK трекеры»?**
DK (Developer Kit) — название трекеров 2-го поколения; приложение 2.0.5 по умолчанию работает в режиме 2.0.
Если у вас **трекеры 1-го поколения** (сопрягаются по Bluetooth): Настройки → версия трекера → переключите на **1.0**
(сначала отвяжите все сопряжённые трекеры).

**В: Переключение на 2.0 не удаётся («version toggle failed»)?**
Сначала отвяжите ВСЕ сопряжённые трекеры в приложении и повторите. Если не помогло —
выполните с root `adb shell setprop persist.pxr.tracking.swiftVersion 2`, перезапустите приложение и попробуйте снова,
и создайте issue с `getprop persist.pxr.tracking.swiftVersion`, `ro.pxr.support.swiftversion` и logcat.

**В: PICO Store показывает «Verification failed: illegal signature» и предлагает купить?**
Это нормально — модифицированный APK подписан тестовым ключом, а не магазинным. Просто закройте окно.
**НЕ** покупайте/восстанавливайте магазинную версию — это затрёт разблокировку.

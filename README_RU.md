# PICO 4 Motion Tracker Unlock (2.0.5)

Полная разблокировка приложения PICO Motion Tracker **2.0.5** для **PICO 4 (стандартная версия)** (A8110 / Phoenix, прошивка 5.13.x).
Приложение включается через **Magisk-модуль**: **обнаружение трекеров работает, установка / обновление / удаление полностью надёжны**. Системный раздел не изменяется — после удаления всё возвращается к заводскому состоянию.

> 📦 Скачать: [Releases](../../releases) → **v2.9.1** (`PICO4_MotionTracker_v2.9.1.zip`: полностью автоматическая совместимость с KarlVis/DirectTouch + очистка остатков v2.0–v2.2; изоляция библиотек из v2.8 сохранена)
> 🔧 Требуется: Magisk 27+, PICO 4 стандартная версия

---

## ❌ Про 5-точечный трекинг (итог реальных тестов — скажем сразу)

**Реально не поддерживается. Все, кто его ждал, — простите, что разочаровали.**

Слой подключения действительно открыт: 5 трекеров спариваются, в приложении выбирается режим на 5 точек.
Но **полный body-solve не работает**: в штатном алгоритме BODYPOSE стандартной версии нет нейросетевых
моделей для forearm / knee (`e2e_*_8_*`), а алгоритм Ultra 1.0.0.54 как замена не подтверждён.
Полный 5-точечный захват на стандартной версии сейчас невозможен — **используйте 2 / 3 точки**.

При этом модуль остаётся полезным:

- полная разблокировка приложения Motion Tracker 2.0.5 на стандартной версии (оригинальный APK, оригинальная подпись)
- нормальное переключение 2 / 3 точек, спаривание / калибровка / список трекеров работают
- по отзывам решает реальные проблемы: трекеры отваливаются в играх (например VRChat),
  окно перекалибровки прерывает использование
- автоматически совместим с KarlVis/DirectTouch — кнопка подтверждения границы больше не «умирает»

## 🆕 v2.9.1: исправление «кнопка подтверждения границы не нажимается» (конфликт с KarlVis/DirectTouch, полностью автоматически)

**Отчёт пользователя**: на v2.0 в окне подтверждения границы / перекалибровки нельзя нажать
кнопку подтверждения — кружок наведения на указателе не появляется; не работает ни контроллером,
ни руками; первая загрузка после установки нормальная, после перезагрузки — воспроизводится.

**Настоящая точка конфликта (подтверждено реверсом KarlVis O1.13.7S)**: DirectTouch из KarlVis —
это LSPosed-модуль (`com.picodirecttouch.lsposed`), который внедряет в `com.picoxr.xrshell`
нативную библиотеку и перехватывает (proxy/orig) обновление луча (**rayProxy**) и курсора/кружка
наведения (**cursorProxy**), а также синхронизацию менеджера панелей. Нормальное взаимодействие
указателя есть только у панелей из его реестра; панель границы/перекалибровки трекеров
(VSTPanel приложения PvrSwift) там не зарегистрирована → кружок не появляется, кнопка не нажимается.
Без модуля трекеров эта панель вообще не возникает, без KarlVis луч работает по оригинальной
логике движка — конфликт именно в наложении. «После первой загрузки норм, после ребута ломается» —
хуки LSPosed активируются после ребута. Полный разбор: [RELEASE_NOTES_v2.9.md](RELEASE_NOTES_v2.9.md).

| Изменение | Описание |
|---|---|
| 🤖 **Автосовместимость с DirectTouch (v2.9.1)** | фоновый наблюдатель `dt_compat.sh` стартует сам (если KarlVis не установлен — сразу выходит, ноль расходов): при появлении панели границы временно `persist.dt.enable 0` (DirectTouch уступает), после исчезновения панели — авто-возврат; если панель висит 120 с и на переднем плане игра (зависло) — панель автоматически закрывается (**трекинг в игре не прерывается**). **Никаких ручных нажатий не нужно** |
| 🧹 **Очистка при обновлении** | удаляет ключи `key_mod_wear_mode` / `key_mod_upper_limit` от старых патченных APK; заодно исчезает побочный эффект v2.0 (принудительный discovery в фоне — у оригинального APK все проверки на месте) |
| 🛟 **Восстановление + диагностика (запасное)** | кнопка «Выполнить (Action)» в Magisk — немедленное восстановление + выгрузка `/sdcard/pico4_diag_*.log` (включая секцию DirectTouch/lspd) |
| 🔒 Архитектура не менялась | оригинальный APK с подписью PICO + приватный каталог библиотек priv-app (путь v2.8) |

> **Пользователям v2.0 / v2.1 / v2.2**: просто прошейте v2.9.1 поверх (тот же id модуля,
> удалять не нужно, привязки сохраняются).
> ✅ Состояние наблюдателя проверено на устройстве автора (A8110 / 5.13.7) от начала до конца;
> «горячее» чтение DirectTouch'ом `persist.dt.enable` ещё подтвердить не удалось (на машине
> автора KarlVis нельзя поставить — другой билд XRShell, риск краха), но есть запасной путь —
> авто-закрытие зависшей панели. Оба пути — без ручных действий.
> Окно, следующее за поворотом головы в dock = Pico2Dock (заменяет системный док
> `com.pvr.shortcut`) × KarlVis (DockHook) — к этому модулю отношения не имеет.

## 🛑 Пользователям v2.7: как можно скорее обновитесь до v2.8 (риск чёрного экрана)

**В v2.7 критический дефект**: библиотеки совместимости смонтированы по глобальному пути `/system/lib64/`.
**Каждый** процесс, загружающий trackingclient — включая `com.pico.xr.openxr_runtime` — получает shim,
что вызывает цикл сбоев OpenXR SIGBUS → накопление tombstone (замерено 447) → падение system_server → **чёрный экран** (только принудительная перезагрузка).

**Исправление в v2.8**: библиотеки перенесены в `/system/priv-app/PvrSwift/lib/arm64/` (приватный каталог приложения).
Видит их только приложение трекеров; OpenXR runtime продолжает использовать стоковую системную библиотеку.
Проверено на устройстве: **0 tombstone, 3 трекера в списке, приложение открывается нормально**.
Установка v2.8 поверх v2.7 — без удаления. APK возвращён к нетронутому оригиналу с подписью PICO, авто-разрыв связи убран (команды вручную — в [RELEASE_NOTES_v2.8.md](RELEASE_NOTES_v2.8.md)).

## 📥 Установка / Обновление / Удаление

### Установка
1. Убедитесь, что есть root (Magisk 27+)
2. Magisk → Модули → Установить из файла → выберите ZIP
3. Перезагрузка
4. Откройте приложение «Motion Tracker»

> **Два tracker-модуля не могут сосуществовать.** Если найден старый `pico4_swift205_libpreload` (v2.0.0), установщик в текущих исходниках прервётся (эта проверка уже в опубликованном ZIP `v2.8.2`). Сначала удалите его (`touch /data/adb/modules/pico4_swift205_libpreload/remove`, перезагрузка), затем прошейте этот ZIP. Оба модуля перекрывают одни и те же APK/so `PvrSwift`, и удаление одного стирает nativeLibraryDir другого.

### Обновление (с любой старой версии, включая v2.0–v2.2)
Просто прошейте ZIP v2.9.1 поверх (**удалять не нужно**); привязки трекеров сохраняются, свойства старого тюнинга восстанавливаются, остатки патченного APK v2.0–v2.2 очищаются.

### Удаление
Удалите модуль в Magisk → перезагрузка. Системный раздел не изменялся — заводская 2.0.4 возвращается сама.

## ❓ FAQ

**Q: Список трекеров пуст?**
Исправлено в v2.6. Если повторится — issue с `adb logcat | grep -E "Swift205Shim|devices:"`.

**Q: Куда делся тюнинг CPU/GPU?**
Перенесён в [pico4-power-mode](https://github.com/hhhbwc/pico4-power-mode). Применяется при включённом режиме производительности, иначе — сток.

**Q: Можно ли ещё прошить старые Performance/EXTREME?**
Старые релизы остались (v2.6), но не поддерживаются; v2.7+ — единая сборка. Для тюнинга используйте pico4-power-mode.

**Q: После OTA системы перестало работать?**
Ожидаемо — перепрошейте модуль и перезагрузитесь.

**Q: Так работает ли 5-точечный полный захват?**
**Нет. Итог реальных тестов (2026-11): не поддерживается.** Спаривание и выбор режима в приложении есть,
но body-solve не работает — в алгоритме стандартной версии нет моделей forearm / knee, замена алгоритмом
Ultra не подтверждена. Используйте 2 / 3 точки. Ещё раз извиняемся перед теми, кто ждал именно 5 точек —
но разблокировка 2.0.5 и стабильные трекеры без отвалов на стандартной версии — реальная польза этого модуля.

**Q: В игре появилось окно подтверждения границы/перекалибровки, кнопка подтверждения не нажимается (на указателе нет кружка, ни контроллером, ни руками)?**
Это наложение KarlVis/DirectTouch и модуля трекеров: DirectTouch перехватывает обновление луча/курсора в xrshell и знает только свои панели — панель границы трекеров в его реестре нет. **Обновитесь до v2.9.1** (установка поверх) — совместимость обеспечивается автоматически при загрузке, без ручных действий: DirectTouch временно уступает на время жизни панели, зависшая панель закрывается сама. Если хотите помочь с диагностикой — приложите `/sdcard/pico4_diag_*.log` к issue. Окно, следующее за поворотом головы в dock — конфликт Pico2Dock × KarlVis, к этому модулю отношения не имеет.
